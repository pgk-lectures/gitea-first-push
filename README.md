# Как загрузить проект на GitVerse

Эта инструкция поможет впервые загрузить готовый проект с компьютера на GitVerse.

Вам не нужно подробно разбираться в Git. Выполняйте действия по порядку и внимательно копируйте команды.

## Что получится в конце

На компьютере останется ваша обычная папка с проектом, а её копия появится в репозитории на GitVerse.

После изменения проекта вы сможете снова отправить новую версию на GitVerse.

## 1. Зарегистрируйтесь на GitVerse

1. Откройте сайт [gitverse.ru](https://gitverse.ru/).
2. Нажмите кнопку регистрации.
3. Укажите свою электронную почту.
4. Придумайте пароль.
5. Придумайте имя пользователя. Оно будет видно другим людям.
6. Подтвердите электронную почту по полученному письму.
7. Войдите в созданный аккаунт.

Запомните логин, пароль и электронную почту. Логин и пароль понадобятся при первой отправке проекта.

## 2. Откройте Git Bash и проверьте Git

1. Откройте меню **Пуск**.
2. Найдите **Git Bash**.
3. Запустите его.
4. Выполните:

```bash
git --version
```

Если появился номер версии, например:

```text
git version 2.51.0
```

значит Git работает и можно продолжать.

## 3. При необходимости укажите своё имя и почту

Эти команды обычно требуется выполнить только один раз на компьютере:

```bash
git config --global user.name "Ваше имя"
git config --global user.email "Ваша электронная почта"
```

Пример:

```bash
git config --global user.name "Ivan Ivanov"
git config --global user.email "ivan@example.com"
```

Вместо данных из примера укажите свои данные.

## 4. Создайте пустой репозиторий на GitVerse

Репозиторий — это место на GitVerse, где будут храниться файлы проекта.

1. Откройте [gitverse.ru](https://gitverse.ru/).
2. Войдите в свой аккаунт.
3. Нажмите кнопку создания нового репозитория.
4. Введите название проекта.
5. Выберите видимость:
   - **Public** — репозиторий виден всем;
   - **Private** — репозиторий виден только вам и приглашённым пользователям.
6. Не создавайте начальный `README`.
7. Не добавляйте `.gitignore` и лицензию.
8. Подтвердите создание репозитория.

После создания откроется страница пустого репозитория.

## 5. Скопируйте адрес репозитория

На странице репозитория выберите способ подключения **HTTPS** и скопируйте адрес.

Адрес будет выглядеть примерно так:

```text
https://gitverse.ru/username/project-name.git
```

Нажмите кнопку копирования справа от адреса.

У каждого репозитория свой адрес. Не копируйте адрес из примера.

## 6. Перейдите к проекту через Git Bash

Все команды нужно выполнять в **Git Bash** внутри папки нужного проекта.

Сначала узнайте путь к проекту. Например:

```text
C:\Users\Student\source\repos\ShoeStoreApp
```

В Git Bash диск `C:` записывается как `/c`. Перейдите в папку:

```bash
cd "/c/Users/Student/source/repos/ShoeStoreApp"
```

Кавычки нужны, если в пути встречаются пробелы.

Посмотрите текущую папку:

```bash
pwd
```

Посмотрите её содержимое:

```bash
ls
```

В списке должны находиться файлы вашего проекта, например файл решения `.sln` или папка с `.csproj`. Если видите файлы другого проекта, не выполняйте `git init`: сначала исправьте путь в команде `cd`.

## 7. Создайте локальный репозиторий

Выполните:

```bash
git init
```

Git начнёт следить за изменениями файлов в этой папке.

Файлы проекта никуда не переместятся и не удалятся.

## 8. Добавьте файлы проекта

Выполните:

```bash
git add .
```

Точка в конце команды означает: добавить все файлы из текущей папки.

Между `add` и точкой должен быть пробел.

## 9. Сохраните первую версию

Выполните:

```bash
git commit -m "init"
```

Коммит — это сохранённая версия проекта.

Текст после `-m` является коротким описанием версии. Вместо `init` можно написать, например:

```bash
git commit -m "Добавил готовый проект"
```

Сообщение нельзя оставлять пустым.

## 10. Назовите основную ветку main

Выполните:

```bash
git branch -M main
```

Эта команда задаёт основной ветке стандартное имя `main`.

## 11. Свяжите папку с репозиторием на GitVerse

Выполните команду, подставив скопированный адрес своего репозитория:

```bash
git remote add origin https://gitverse.ru/username/project-name.git
```

Например, если пользователь называется `student` и репозиторий называется `shoe-store`, команда будет такой:

```bash
git remote add origin https://gitverse.ru/student/shoe-store.git
```

Не используйте этот пример без изменений. В команде должен быть адрес именно вашего репозитория.

## 12. Отправьте проект на GitVerse

Выполните:

```bash
git push -u origin main
```

При первой отправке Git Bash попросит данные GitVerse:

```text
Username: ваш логин GitVerse
Password: ваш пароль GitVerse
```

При вводе пароля символы могут не отображаться. Это нормально: введите пароль и нажмите Enter.

## Все основные команды вместе

Выполняйте их по одной, а не вставляйте всё одной строкой:

```bash
git init
git add .
git commit -m "init"
git branch -M main
git remote add origin https://gitverse.ru/username/project-name.git
git push -u origin main
```

В пятой команде обязательно замените пример на адрес своего репозитория.

## 13. Проверьте результат

1. Вернитесь на страницу репозитория GitVerse в браузере.
2. Обновите страницу.
3. Убедитесь, что на странице появились файлы и папки проекта.

Если файлы появились, проект успешно загружен.

## 14. Измените проект и отправьте новую версию

После первого push внесите небольшое изменение, чтобы научиться отправлять следующие версии проекта.

### Измените проект

1. Вернитесь в Visual Studio.
2. Откройте одну из форм проекта.
3. Измените текст любой надписи или кнопки. Например, замените заголовок формы.
4. Сохраните изменения через **Файл → Сохранить всё**.

Можно изменить и C#-код. Главное, чтобы файл действительно изменился и был сохранён.

### Вернитесь в папку проекта

Откройте Git Bash и снова перейдите в папку своего проекта:

```bash
cd "/c/Users/Student/source/repos/ShoeStoreApp"
```

Вместо примера укажите настоящий путь к своему проекту.

### Отправьте изменения

Выполните три команды:

```bash
git add .
git commit -m "update"
git push
```

Вместо `update` можно написать любой текст. Смысл сообщения в этой работе не проверяется.

Для следующих отправок достаточно обычной команды `git push`. Параметры `-u origin main` были нужны только при первой отправке.

### Проверьте новую версию

1. Откройте свой репозиторий на GitVerse.
2. Обновите страницу.
3. Убедитесь, что изменённый файл появился в новой версии.
4. Откройте историю коммитов и убедитесь, что появился новый коммит.

## Команды для отправки следующих изменений

Каждый раз после изменения проекта выполняйте:

```bash
cd "/c/путь/к/вашему/проекту"
git add .
git commit -m "update"
git push
```

Повторно выполнять следующие команды не нужно:

```bash
git init
git branch -M main
git remote add origin ...
```

Они использовались только при первоначальной настройке проекта.

## Частые ошибки

### Git Bash открыт не в той папке

Выполните `pwd` и `ls`. Затем перейдите в нужную папку через `cd`.

### Please tell me who you are

Git не знает имя или почту автора. Выполните:

```bash
git config --global user.name "Ваше имя"
git config --global user.email "Ваша электронная почта"
```

После этого снова выполните команду `git commit`.

### Remote origin already exists

Связь с удалённым репозиторием уже была добавлена. Повторно выполнять `git remote add origin` не нужно.

Проверьте сохранённый адрес:

```bash
git remote -v
```

### Repository not found

Проверьте три вещи:

- адрес репозитория скопирован полностью;
- репозиторий существует;
- введены логин и пароль правильного аккаунта GitVerse.

### Файлы не появились на GitVerse

Убедитесь, что команда `git push` завершилась без ошибки. После отправки обновите страницу репозитория в браузере.

## Коротко: что делает каждая команда

| Команда | Что она делает |
| --- | --- |
| `git init` | Включает Git в текущей папке |
| `git add .` | Подготавливает все файлы к сохранению |
| `git commit -m "init"` | Сохраняет первую версию проекта |
| `git branch -M main` | Называет основную ветку `main` |
| `git remote add origin ...` | Связывает папку с репозиторием GitVerse |
| `git push -u origin main` | Первый раз отправляет проект на GitVerse |
| `git push` | Отправляет следующие версии проекта |
